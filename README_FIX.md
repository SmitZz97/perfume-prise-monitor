# Исправления perfume-browser-agent

Изменена распакованная копия предоставленного архива. Файлы на диске C: автоматически не изменялись. Текущий живой сбор с магазинов не объявляется работающим: в облачном запуске подтверждено 0 цен.

## Установка обновления на Windows

1. Закройте программу и сделайте копию исходных Python-файлов.
2. Распакуйте perfume-browser-agent-update.zip непосредственно в C:\Users\User\perfume-browser-agent с заменой одноимённых исходников.
3. supplier_links.json, products.csv и supplier_browser_profile в обновление не входят: сохраните свои существующие файлы и профиль. Механизм launch_persistent_context, путь профиля и способ авторизации Delice Opt не изменены.
4. В используемом окружении Python установите зависимости: `python -m pip install -r requirements.txt`. Если Chromium ещё не установлен: `python -m playwright install chromium`.
5. Создайте локальный входной Excel: `python create_test_input.py`. Скрипт содержит только пять публичных названий/объёмов, без цен и ссылок поставщика, и не перезаписывает существующий файл.
6. Запуск пяти тестовых ароматов: `python batch_monitor.py --input test_products.xlsx --output monitoring.xlsx`.

Тесты: `python -m pytest tests -q`. Старые файлы test_*.py в корне запускают интерактивные сетевые исследования при импорте, поэтому рабочий набор тестов находится в tests/.

## Что исправлено

- discover_perfumes.py: новый рабочий путь отделяет поисковый запрос от концентрации; EDP/EDT не требуются в транслитерированном URL. Кандидат не считается совпадением до проверки первичной карточки. Исторические функции сохранены для совместимости, но основной запуск использует collect и monitor_core.
- monitor_core.py: строгое сравнение бренда/названия, EDP/EDT/Extrait/Parfum и объёма, исключение тестеров/наборов, проверка JSON-LD Product/Offer, отказ от диапазонов, условных/просроченных/неоднозначных цен. Aventus и Aventus Cologne не смешиваются. DOM-резерв ограничен основной областью товара; рекомендации и скрытые цены не используются. Неизвестные наличие/продавец не выдумываются.
- browser_access.py: защита до отображения HTML, robots.txt с шаблонами, HTTPS с проверкой сертификатов, отсутствие повторов после защиты. Запросы не GET и посторонние домены отклоняются, что может ограничить динамический поиск. Есть журнал отклонённых ресурсов. Не используются stealth, смена IP, отключение TLS или обход challenge.
- batch_monitor.py: принимает лист «Ароматы» или первый лист с колонками «Аромат» и «Объём, мл», обрабатывает все строки, сохраняет промежуточный Excel после каждой строки атомарно. Сбой магазина, закупки или входной строки не скрывает остальные результаты. Добавлен лист «Диагностика».
- supplier_compare.py: удалено использование последней суммы родительского контейнера и сохранённых цен как текущей закупки. Цена читается только из явного поля своей строки предложения; неоднозначность даёт пустое значение. Концентрация проверяется обязательно. Запомненная ссылка находится и для запроса с EDP. Повреждённый реестр ссылок не обнуляется. Автоматический повторный мониторинг не переписывает реестр; новая явно переданная ссылка записывается атомарно.
- pricing_recommendation.py: Decimal вместо небезопасных округлений float, конечность/положительность значений, минимальная наценка 15%, отсутствие расчёта по неподтверждённой закупке.
- perfume_monitor.py: кнопка проверки вызывает исправленный поисковый путь вместо старого permissive v9; строгий отбор строк каталога; полный цикл передаёт именно свежий CSV сравнения.

## Минимальная цена

При закупке C, доставке D, прочих фиксированных расходах O и доле комиссии/налога f:

`P_min = ceil((C × 1.15 + D + O) / (1 − f))`

`Прибыль = P × (1 − f) − C − D − O`

Это гарантирует прибыль после указанных расходов не менее 15% закупки при используемой модели расходов; это не маржа 15% от выручки. Рекомендуемая цена никогда не ниже порога. В batch-конкурентный ориентир попадают только подтверждённые предложения InStock без стороннего продавца. Без надёжных конкурентов используется рассчитанный порог, если закупка подтверждена. Без закупки порог/рекомендация/прибыль пусты.

Неучтённые комиссии, логистика или налоги не могут учитываться автоматически. Передайте фактические расходы через --shipping, --other, --commission-pct, --tax-pct. Налоги здесь моделируются процентом выручки, а не произвольной системой налогообложения.

## Итог проверки

56 passed. Проверены синтаксис семи модулей, пять входных ароматов, 25 диагностических записей, отсутствие синтетических цен в итоговом Excel и побайтовая неизменность supplier_links.json. Тестовые цены используются только в локальных HTML-фикстурах и временных файлах pytest.

Живой запуск выполнен в Linux/Chromium, а не в вашем Windows-профиле:

`python batch_monitor.py --input test_products.xlsx --output monitoring.xlsx --headless --browser-executable /usr/bin/chromium --verified-transport`

--verified-transport — ограниченный режим облачного отображения: браузер исполняет разрешённый HTML/JS, ресурсы получает TLS-проверяемый requests с унаследованным прокси. Это не обход защиты и не проверка локального Windows-окружения. Обычный запуск использует транспорт Playwright с проверкой TLS.

Точная причина недоступности динамического интерфейса Золотого Яблока/Лэтуаль не установлена: возможны ограничения отклонённых внешних ресурсов/не-GET запросов и особенности отображения. Это не доказательство отсутствия товара и не подтверждение актуальности CSS-селекторов этих магазинов. На локальном компьютере необходима повторная проверка, поэтому результат не маркируется как полностью рабочая интеграция.
